# Chấm công Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** An admin-only "Chấm công" tab that logs edited sets (person + price item) and totals each person's money per month.

**Architecture:**
- Entries live in `orgs/{org}/payroll`; the editor and price lists live in `orgs/{org}/payrollConfig/main`. Both are admin-only by security rules.
- Pure month math sits in `domain/payroll.ts`, the Firestore listeners in `data/payroll.ts`, and the UI is a lazy tab plus a Thêm sub-screen.

**Tech Stack:** Vite + Preact + signals, Firebase Firestore, vitest, rules-unit-testing (runs in CI), Python Playwright smoke against the mock build.

**Spec:** `docs/superpowers/specs/2026-11-26-cham-cong-design.md`

## Global Constraints
- Only the org admin sees the tab, the settings screen and the data. Rules enforce this.
- Entry: `{ date: 'YYYY-MM-DD', personId, person, item, price, weddingId?, weddingName?, note?, createdAt, updatedAt }`. `price` is an int in 0…100,000,000. Strings are ≤ 200 chars; the note is ≤ 1000.
- Totals group by `personId` and show the current name from config, falling back to the `person` snapshot.
- Money format: `600.000đ`.
- Seed items (names and prices), in this order:
  - Chỉnh sửa ảnh đính hôn phóng sự – 2 máy: 400000
  - Chỉnh sửa ảnh đính hôn truyền thống: 250000
  - Chỉnh sửa ảnh cưới phóng sự cơ bản – 2 máy: 600000
  - Chỉnh sửa ảnh cưới phóng sự cơ bản – 3 máy: 800000
  - Chỉnh sửa ảnh tiệc báo hỷ phóng sự: 400000
  - Chỉnh sửa ảnh tiệc báo hỷ truyền thống: 250000
  - Chỉnh sửa ảnh hôn phối phóng sự: 400000
  - Chỉnh sửa ảnh outdoor cơ bản – 2 máy: 600000
  - Chỉnh sửa ảnh outdoor cơ bản – 3 máy: 900000
- Nav order for the admin: Sắp tới, Việc, Thợ, Báo giá, Chấm công, Thêm. Others keep 5 tabs. No horizontal overflow at 360px.
- Sổ Tay stays ≤ 200KB gzip. Light and dark themes.
- The rules change must be published in the Firebase console at push time.

## Review Focus
1. **Month boundaries.** An entry dated the 30th/31st is counted in its own month and never in the next one. Test in Task 1.
2. **A person renamed after logging** shows as one row with the new name. A person removed from the list still shows, using the name snapshot. Test in Task 1.
3. **A price changed after logging** leaves past totals unchanged. Test in Task 1 (totals use `entry.price`).
4. **An editor or viewer account** never gets the tab, and a direct read of `payroll` fails. Tests in Task 2 (rules) and Task 3 (smoke).
5. **A money input like "600.000" or "600k"** in settings parses to 600000. Test in Task 1 (`parseMoney`).

### Task 1: Pure payroll logic
**Files:** Create `web/src/domain/payroll.ts`; Test `web/test/payroll.test.ts`
**Produces:**
- `PayEntry`, `PayPerson { id; name; hidden? }`, `PayItem { id; name; price; hidden? }`, `PayConfig { people: PayPerson[]; items: PayItem[] }`
- `SEED_ITEMS: PayItem[]` (ids `i1`…`i9`)
- `money(n: number): string`, giving `"600.000đ"`
- `parseMoney(s: string): number | null`:
  - `"600.000"`, `"600000"`, `"600k"` → 600000; `"1,2tr"` → 1200000
  - `""` or garbage → null
- `monthOf(date): 'YYYY-MM'`, `shiftMonth(m, ±1)`
- `monthTotals(entries, month, cfg): { personId; name; count; total; entries: PayEntry[] }[]`:
  - Only entries of `month`. Sorted by total, highest first. Entries inside a row sorted by date, then createdAt.
  - `name` = the current config name, else the snapshot.
- `statement(row, month): string`. Exact text:
  ```
  CHẤM CÔNG THÁNG 11/2026 – Linh
  - 22/11 Chỉnh sửa ảnh cưới phóng sự cơ bản – 2 máy (Trà My & Phát Lộc): 600.000đ
  …
  Tổng: 8 bộ – 3.650.000đ
  ```
  The wedding part in brackets appears only when `weddingName` is set.

- [ ] Write tests:
  - `money`
  - `parseMoney` (all cases above)
  - `shiftMonth('2026-01',-1) == '2025-12'`
  - `monthTotals`:
    - drops the 2026-12-01 entry from November
    - a renamed person shows the new name in one row
    - a removed person shows the snapshot
    - totals use the stored price
  - `statement` exact text
- [ ] Run `npx vitest run test/payroll.test.ts`. Expected: FAIL (module missing).
- [ ] Implement.
- [ ] Run again. Expected: PASS.
- [ ] Commit `feat(payroll): month totals and statements`.

### Task 3: Tab, Ghi công sheet, settings
**Files:**
- Create `web/src/ui/Payroll.tsx` (the tab and the entry sheet) and `web/src/ui/PayrollSettings.tsx`
- Modify:
  - `web/src/ui/Shell.tsx`: `Tab` gains `'payroll'`; the nav item `['payroll','Chấm công',IWallet]` is admin-only
  - `web/src/ui/App.tsx` (lazy render)
  - `web/src/ui/More.tsx`: sub `'payroll'` titled "Chấm công", with an entry shown to the admin
  - `web/src/ui/icons.tsx` (`IWallet`), `web/src/styles.css`
- Test `web/test/smoke.py`
**UI:**
- **Tab:**
  - h1 "Chấm công" and a month switcher (‹ › buttons labelled "Tháng trước" / "Tháng sau"; the label shows "Tháng 11/2026").
  - A "Ghi công" button.
  - Person rows: buttons with `aria-expanded`, showing name · "n bộ" · money.
  - An open row lists its entries (date, item, wedding, money, Sửa, Xoá with confirm) and a "Copy bảng" button (toast "Đã copy bảng của <name>").
  - A "Tổng" line.
  - Empty month: "Chưa ghi công tháng này."
  - No people yet: a hint linking to Thêm → Chấm công.
- **Ghi công sheet:**
  - Fields:
    - Người edit (select of non-hidden people)
    - Hạng mục (select "name – 600.000đ")
    - Ngày (date, defaults to today)
    - Đám cưới (optional select of `visibleWeddings` within ±60 days of the chosen date, sorted by date: "dd/mm Bride & Groom")
    - Ghi chú (optional)
  - Buttons: Lưu, Huỷ. Person and item are required.
  - Editing an entry reuses the sheet.
- **Settings:**
  - Two lists, "Người edit" and "Bảng giá chỉnh sửa".
  - Add rows; edit name and price inputs (price via `parseMoney`, an invalid price shows a field error); Ẩn/Hiện toggles.
  - Saves on blur.
